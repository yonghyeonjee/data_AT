# 구독 페이지 유입 추적 붙이기 (SUB v1.5 · mvp_225)

구독 문의 · 간편 문의 · B2B 구독 접수에 **어디서 와서 신청했는지**를 싣는다.
데이터센터는 이미 받을 준비가 돼 있다(2026-10-20). GAS 는 고칠 필요 없다(받은 필드를 그대로 넘긴다).

## 담당자 화면에 보이는 모양
상담의 유입경로가 이렇게 찍힌다.
- `B2B 구독 폼 (네이버 검색 → 사이트 내 · 블로그 글 119)`
- `구독 폼 (crm_manual/lms/tabs12 → 사이트 내 · 메인)` — 문자 링크로 메인에 왔다가 구독 페이지로
- `구독 폼 (인스타그램 · 재방문 → 사이트 내 · 상품 상세 1000000918)` — 30일 안에 인스타그램으로 왔던 사람이 다시 와서
- `구독 폼 (직접 유입)`

문자 캠페인으로 첫 페이지에 들어왔다가 다른 페이지를 거쳐 신청해도 발송 링크 관리 [문의] 숫자에 잡힌다.
검색어는 브라우저가 넘겨주지 않아 남지 않는다(네이버·구글 모두).

## 붙이는 곳 (test_subscribe.php 에 먼저)
1. `sub_track.html` 의 `<script>` 블록 전체를 구독 페이지 `</style>` 바로 아래(= `<div id="samsung-sub-page">` 위)에 붙인다.
2. 접수 세 곳의 `fetch(` 바로 윗줄에 한 줄씩 넣는다.
   ```js
   if (window.samTrackInto) window.samTrackInto(data);
   ```
   - 일반 신청서: `fetch(CONFIG.gasUrl, {` 위
   - 간편 문의(evt=simple): `fetch(GAS_URL, {` 위 (첫 번째)
   - B2B 구독(evt=b2b): `fetch(GAS_URL, {` 위 (두 번째)
3. (권장) 고도몰 **공통 하단**(모든 페이지)에도 같은 `<script>` 블록을 넣는다.
   없으면 '처음 들어온 곳'이 구독 페이지 자신이 되어, 다른 페이지로 들어와 돌아다닌 사람의 외부 출처(네이버 검색 등)를 못 잡는다.
   두 번 들어가도 한 번만 돈다.

## 싣는 값 (`raw_payload` 에 그대로 저장)
| 키 | 뜻 |
|---|---|
| `referrerFull` | 직전 페이지 전체 주소 (예: 블로그 글 sno=119) |
| `entryRef` · `entryLanding` · `entryAt` | 이번 방문의 첫 페이지와 그 페이지로 오기 전 주소 |
| `lastExtRef` · `lastExtLanding` · `lastExtAt` | 30일 안 마지막 외부 유입·UTM 링크 |
| `gaClientId` | GA4 사용자 ID (`_ga` 쿠키) — GA4 탐색에서 그 사람의 세션을 찾을 때 |

고도몰 템플릿 치환 규칙대로 여는 중괄호 뒤에는 늘 공백이 있다.
